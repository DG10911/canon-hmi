2 — CANON Validation Architecture

Validation is deterministic code. The LLM may explain a failure. It may not decide validity.



Pipeline

Proposal (JSON)
  → Schema validation (JSON Schema / Pydantic / Zod)
    → Referential validation (ids exist in machine model)
      → Type / unit / range validation
        → Command contract validation
          → HMI component schema validation
            → PLC contract validation (address exists, access mode)
              → Test presence (P1)
                → Result object (pass/fail + codes + evidence)

A single fail code blocks approval. Partial HMI generation is allowed only if the engineer explicitly accepts a proposal with droppedWidgets[].
