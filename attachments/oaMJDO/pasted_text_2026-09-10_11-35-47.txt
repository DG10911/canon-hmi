0. NON-NEGOTIABLE COMPETITION TARGET

Build ASSETFLOW / CANON specifically to solve the following official problem statement:

PS2 — Dynamic screen at runtime and control of machines via HMI

Problem Statement

HMI engineering is heavily dependent on the manual creation and maintenance of screens, navigation, and visualization logic.

As industrial systems evolve, engineers spend significant effort updating HMI assets to reflect changes in:

* machine configurations
* PLC tags
* alarms
* process requirements
* I/O
* asset structures
* communication configurations
* engineering documentation

Approximately 50–70% of total HMI lifecycle effort is consumed by screen creation, maintenance, and enhancement activities, resulting in:

* increased engineering cost
* longer delivery cycles
* repetitive engineering work
* slower commissioning
* difficult change propagation
* increased maintenance effort

⸻

62. FINAL PRODUCT STATEMENT

CANON transforms HMI engineering from manually maintained screens into machine-context-driven dynamic interfaces.

It creates a unified machine context from PLC/controller tags, I/O configuration, asset hierarchies, alarm definitions, communication configurations and machine documentation.

AI interprets operator intent against that context.

A canonical engineering model determines what machine objects, signals and commands actually exist.

A deterministic validation layer verifies bindings and command contracts.

A dynamic HMI compiler generates the appropriate machine-specific interface at runtime.

Operators can interact with the machine through that HMI while the PLC remains the authoritative control layer.

When engineering changes occur, CANON identifies downstream dependencies, regenerates affected HMI representations and supports regression verification.
