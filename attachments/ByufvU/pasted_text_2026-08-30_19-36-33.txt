2. PROBLEM UNDERSTANDING & USE-CASE SELECTION
2.1 The Core Problem
According to the IEA 4E Energy in Motor Systems Annex (EMSA, 2023), electric motor systems consume approximately 53% of global electricity and ~72% of industrial electricity. Within motor-driven loads, pumps account for ~22% and compressors for ~25% of total motor-system energy use. The IEA further estimates that existing efficiency measures can reduce motor-system demand by 20–30% with short payback periods — yet the majority of installations still rely on fixed-speed motors with mechanical throttling, dissipating energy as heat and pressure drop across valves and dampers.

The hackathon problem statement calls for a system that does not merely monitor but actively optimizes — integrating PLC control, HMI visualization, VFD speed regulation, and energy metering into a closed-loop intelligence platform.

2.2 Chosen Use Case: Smart Water Pumping Station
We propose a municipal/industrial water pumping station with the following characteristics:

Parameter	Specification

Operating Profile	Variable demand (40–100% flow, diurnal pattern)
System Curve	Friction-dominated (~80% friction head, ~20% static head at design flow)

Why this use case:

The process is simple enough to be fully understood by judges while complex enough to demonstrate real engineering depth

5.3 Key Control Logic: PID Pressure Control (Derivative on Measurement)
text

(* PID Pressure Control — Structured Text *)
(* Maintains header pressure by modulating VFD speed *)
(* Derivative on measurement to avoid derivative kick on SP changes *)

// Inputs
Pressure_SP    : REAL := 4.5;    // Header pressure setpoint (bar)
Pressure_PV    : REAL;           // Measured pressure from transmitter (4-20mA)
Mode           : INT;            // 0=Manual, 1=Auto

// PID Parameters (tuned for pump dynamics)
Kp             : REAL := 1.2;    // Proportional gain
Ki             : REAL := 0.15;   // Integral gain (1/s)
Kd             : REAL := 0.05;   // Derivative gain (s)

// Outputs
VFD_Speed_SP   : REAL;           // 0.0 to 50.0 Hz
VFD_Run_Cmd    : BOOL;

// Internal
PrevPV         : REAL;           // Previous process variable (for derivative)

// PID execution (called every 20ms)
IF Mode = 1 THEN  // Auto mode
    Error := Pressure_SP - Pressure_PV;
    
    // Anti-windup: clamp integral when output is saturated
    IF VFD_Speed_SP < 50.0 AND VFD_Speed_SP > 0.0 THEN
        Integral := Integral + Error * CycleTime;
    END_IF;
    Integral := LIMIT(-50.0/Ki, Integral, 50.0/Ki);
    
    // Derivative on MEASUREMENT (not error) — avoids output spike
    // when setpoint changes suddenly (textbook-correct form)
    Derivative := -(Pressure_PV - PrevPV) / CycleTime;
    PrevPV := Pressure_PV;
    
    VFD_Speed_SP := Kp * Error + Ki * Integral + Kd * Derivative;
    VFD_Speed_SP := LIMIT(15.0, VFD_Speed_SP, 50.0);  // Min 15Hz, Max 50Hz
    
    VFD_Run_Cmd := TRUE;
ELSE  // Manual mode
    Integral := 0.0;  // Reset for bumpless transfer
    PrevPV := Pressure_PV;  // Track PV to avoid bump on return to Auto
    // VFD_Speed_SP set by operator via HMI
END_IF;
5.4 Safety Interlock Philosophy
Critical design principle: All safety-critical interlocks reside in the PLC, not the HMI. The HMI is a visualization and command interface only; it cannot override safety logic. This ensures that even if the HMI fails or loses communication, the PLC maintains safe operation.

Key interlocks:

Dry-run protection: If flow meter reads < 5% of rated AND pump running > 10s → trip VFD
Over-current: VFD fault word bit → immediate stop, alarm generation
Over-temperature: Motor winding temp > 130°C (Class F, via PT100 input to ATV630) → derate, then trip
Under-voltage: Supply voltage < 85% nominal (from PM5300) → controlled shutdown
Communication loss: If VFD Modbus timeout > 5s → safe stop, alarm
Emergency stop: Hardwired E-stop triggers the ATV630's embedded SIL 3 Safe Torque Off (STO) per IEC 61508, removing motor torque independently of the PLC scan. The STO circuit is wired directly to the safety relay chain and does not depend on any communication bus or PLC logic cycle.

6.3 The Key Metric: Specific Energy Consumption (SEC)
SEC = Total Energy Consumed (kWh) / Total Water Pumped (m³)

This single metric captures the overall efficiency of the pumping system. It requires both the energy meter (kWh from PM5300) and the flow meter (cumulative m³) — making it a true system-level KPI that validates the entire automation loop. A rising SEC indicates degradation (worn impeller, clogged filter, excessive throttling). A falling SEC confirms that the VFD optimization is working. The dashboard will track SEC continuously and alert operators when it deviates from baseline by more than a configurable threshold (e.g., 10%).

Static head (elevation lift, fixed back-pressure) is constant regardless of flow and does not follow the cube law. The pump must overcome this head even at zero flow.
Friction head (pipe friction, fittings, valve losses) varies with the square of flow and is the component where VFD speed reduction delivers cubic savings.
The flatter the system curve (i.e., the higher the static head fraction), the less effective VFD speed reduction becomes, because the pump cannot slow below the speed required to overcome the static head before flow ceases.

Our design assumption: The target application is a friction-dominated distribution system (long mains, moderate lift), with an estimated ~80% friction head / ~20% static head at design flow. In this configuration, affinity-law savings are largely realized, and we project 40–50% energy reduction at typical partial-load operating points.

For static-head-dominated scenarios (e.g., high-lift applications with short piping), we conservatively project 25–35% savings rather than the theoretical cube-law maximum.

Commissioning calibration: During system commissioning, the optimization engine will characterize the actual system curve by logging operating points (flow from the electromagnetic flow meter, head from the pressure transmitter, speed from the VFD, power from the PM5300) across the operating range. From this measured data, it computes the static/friction split and derives the achievable-vs-theoretical savings ratio for the specific installation. All subsequent energy optimization recommendations are based on this calibrated model, not on the ideal cube law alone.

This approach ensures that the system's energy savings claims remain credible and verifiable regardless of the actual hydraulic configuration.

2.1 The Core Problem
According to the IEA 4E Energy in Motor Systems Annex (EMSA, 2023), electric motor systems consume approximately 53% of global electricity and ~72% of industrial electricity. Within motor-driven loads, pumps account for ~22% and compressors for ~25% of total motor-system energy use. The IEA further estimates that existing efficiency measures can reduce motor-system demand by 20–30% with short payback periods — yet the majority of installations still rely on fixed-speed motors with mechanical throttling, dissipating energy as heat and pressure drop across valves and dampers.

The hackathon problem statement calls for a system that does not merely monitor but actively optimizes — integrating PLC control, HMI visualization, VFD speed regulation, and energy metering into a closed-loop intelligence platform.

5.3 Key Control Logic: PID Pressure Control (Derivative on Measurement)
text

(* PID Pressure Control — Structured Text *)
(* Maintains header pressure by modulating VFD speed *)
(* Derivative on measurement to avoid derivative kick on SP changes *)

// Inputs
Pressure_SP    : REAL := 4.5;    // Header pressure setpoint (bar)
Pressure_PV    : REAL;           // Measured pressure from transmitter
Mode           : INT;            // 0=Manual, 1=Auto

// PID Parameters (tuned for pump dynamics)
Kp             : REAL := 1.2;    // Proportional gain
Ki             : REAL := 0.15;   // Integral gain (1/s)
Kd             : REAL := 0.05;   // Derivative gain (s)

// Outputs
VFD_Speed_SP   : REAL;           // 0.0 to 50.0 Hz
VFD_Run_Cmd    : BOOL;

// Internal
PrevPV         : REAL;           // Previous process variable (for derivative)

// PID execution (called every 20ms)
IF Mode = 1 THEN  // Auto mode
    Error := Pressure_SP - Pressure_PV;
    
    // Anti-windup: clamp integral when output is saturated
    IF VFD_Speed_SP < 50.0 AND VFD_Speed_SP > 0.0 THEN
        Integral := Integral + Error * CycleTime;
    END_IF;
    Integral := LIMIT(-50.0/Ki, Integral, 50.0/Ki);
    
    // Derivative on MEASUREMENT (not error) — avoids output spike
    // when setpoint changes suddenly (textbook-correct form)
    Derivative := -(Pressure_PV - PrevPV) / CycleTime;
    PrevPV := Pressure_PV;
    
    VFD_Speed_SP := Kp * Error + Ki * Integral + Kd * Derivative;
    VFD_Speed_SP := LIMIT(15.0, VFD_Speed_SP, 50.0);  // Min 15Hz, Max 50Hz
    
    VFD_Run_Cmd := TRUE;
ELSE  // Manual mode
    Integral := 0.0;  // Reset for bumpless transfer
    PrevPV := Pressure_PV;  // Track PV to avoid bump on return to Auto
    // VFD_Speed_SP set by operator via HMI
END_IF;
5.4 Safety Interlock Philosophy
Critical design principle: All safety-critical interlocks reside in the PLC, not the HMI. The HMI is a visualization and command interface only; it cannot override safety logic. This ensures that even if the HMI fails or loses communication, the PLC maintains safe operation.

Key interlocks:

Dry-run protection: If flow < 5% of rated AND pump running > 10s → trip VFD
Over-current: VFD fault word bit → immediate stop, alarm generation
Over-temperature: Motor winding temp > 130°C (Class F, via PT100 input to ATV630) → derate, then trip
Under-voltage: Supply voltage < 85% nominal (from PM5300) → controlled shutdown
Communication loss: If VFD Modbus timeout > 5s → safe stop, alarm
Emergency stop: Hardwired E-stop triggers the ATV630's embedded SIL 3 Safe Torque Off (STO) per IEC 61508, removing motor torque independently of the PLC scan. The STO circuit is wired directly to the safety relay chain and does not depend on any communication bus or PLC logic cycle.

Static head (elevation lift, fixed back-pressure) is constant regardless of flow and does not follow the cube law. The pump must overcome this head even at zero flow.
Friction head (pipe friction, fittings, valve losses) varies with the square of flow and is the component where VFD speed reduction delivers cubic savings.
The flatter the system curve (i.e., the higher the static head fraction), the less effective VFD speed reduction becomes, because the pump cannot slow below the speed required to overcome the static head before flow ceases.

Our design assumption: The target application is a friction-dominated distribution system (long mains, moderate lift), with an estimated ~80% friction head / ~20% static head at design flow. In this configuration, affinity-law savings are largely realized, and we project 40–50% energy reduction at typical partial-load operating points.

For static-head-dominated scenarios (e.g., high-lift applications with short piping), we conservatively project 25–35% savings rather than the theoretical cube-law maximum.

Commissioning calibration: During system commissioning, the optimization engine will characterize the actual system curve by logging operating points (flow, head, speed, power) across the operating range. From this measured data, it computes the static/friction split and derives the achievable-vs-theoretical savings ratio for the specific installation. All subsequent energy optimization recommendations are based on this calibrated model, not on the ideal cube law alone.

This approach ensures that the system's energy savings claims remain credible and verifiable regardless of the actual hydraulic configuration.

5.3 Key Control Logic: PID Pressure Control
text

(* PID Pressure Control — Structured Text *)
(* Maintains header pressure by modulating VFD speed *)

// Inputs
Pressure_SP    : REAL := 4.5;    // Header pressure setpoint (bar)
Pressure_PV    : REAL;           // Measured pressure from transmitter
Mode           : INT;            // 0=Manual, 1=Auto

// PID Parameters (tuned for pump dynamics)
Kp             : REAL := 1.2;    // Proportional gain
Ki             : REAL := 0.15;   // Integral gain (1/s)
Kd             : REAL := 0.05;   // Derivative gain (s)

// Outputs
VFD_Speed_SP   : REAL;           // 0.0 to 50.0 Hz
VFD_Run_Cmd    : BOOL;

// PID execution (called every 20ms)
IF Mode = 1 THEN  // Auto mode
    Error := Pressure_SP - Pressure_PV;
    
    // Anti-windup: clamp integral when output is saturated
    IF VFD_Speed_SP < 50.0 AND VFD_Speed_SP > 0.0 THEN
        Integral := Integral + Error * CycleTime;
    END_IF;
    Integral := LIMIT(-50.0/Ki, Integral, 50.0/Ki);
    
    Derivative := (Error - PrevError) / CycleTime;
    PrevError := Error;
    
    VFD_Speed_SP := Kp * Error + Ki * Integral + Kd * Derivative;
    VFD_Speed_SP := LIMIT(15.0, VFD_Speed_SP, 50.0);  // Min 15Hz, Max 50Hz
    
    VFD_Run_Cmd := TRUE;
ELSE  // Manual mode
    Integral := 0.0;  // Reset for bumpless transfer
    // VFD_Speed_SP set by operator via HMI
END_IF;
5.4 Safety Interlock Philosophy
Critical design principle: All safety-critical interlocks reside in the PLC, not the HMI. The HMI is a visualization and command interface only; it cannot override safety logic. This ensures that even if the HMI fails or loses communication, the PLC maintains safe operation.

Key interlocks:

Dry-run protection: If flow < 5% of rated AND pump running > 10s → trip VFD
Over-current: VFD fault word bit → immediate stop, alarm generation
Over-temperature: Motor winding temp > 130°C (Class F) → derate, then trip
Under-voltage: Supply voltage < 85% nominal → controlled shutdown
Communication loss: If VFD Modbus timeout > 5s → safe stop, alarm
Emergency stop: Hardwired E-stop → immediate VFD disable (bypasses PLC scan)

6.3 The Key Metric: Specific Energy Consumption (SEC)
SEC = Total Energy Consumed (kWh) / Total Water Pumped (m³)

This single metric captures the overall efficiency of the pumping system. A rising SEC indicates degradation (worn impeller, clogged filter, excessive throttling). A falling SEC confirms that the VFD optimization is working. The dashboard will track SEC continuously and alert operators when it deviates from baseline by more than a configurable threshold (e.g., 10%).

This cubic relationship means that even modest speed reductions yield dramatic power savings:

VFD Speed	Flow Rate	Power Draw	Energy Saved vs. Full Speed
100%	100%	100%	—
90%	90%	72.9%	27.1%
80%	80%	51.2%	48.8%
70%	70%	34.3%	65.7%
60%	60%	21.6%	78.4%
The key insight: A fixed-speed pump throttled by a valve to 80% flow still consumes ~95% of full power (the valve dissipates the excess energy as heat and noise). The same 80% flow achieved by reducing VFD speed to 80% consumes only ~51% power. The difference — roughly 44% of rated power — is pure waste eliminated by the VFD.

For a 30 kW pump running 16 hours/day at an average of 80% speed:

Fixed-speed + valve: 30 kW × 0.95 × 16h × 365 = 166,440 kWh/year
VFD speed control: 30 kW × 0.512 × 16h × 365 = 89,518 kWh/year
Annual savings: 76,922 kWh (₹6.15 lakhs at ₹8/kWh)
CO₂ reduction: ~63 tonnes/year (at 0.82 kg CO₂/kWh grid average)

FUNCTION_BLOCK FB_MPC_MotorControl
(* Model Predictive Control for VFD-driven motor *)
(* Optimizes speed setpoint for minimum energy while meeting process demands *)

VAR_INPUT
    ProcessDemand       : REAL;     // Required process output (e.g., flow rate m³/h)
    MeasuredOutput      : REAL;     // Actual process output
    MotorCurrent        : REAL;     // From VFD feedback (A)
    MotorPower          : REAL;     // From VFD feedback (kW)
    MotorTemp           : REAL;     // Motor winding temperature (°C)
    AmbientTemp         : REAL;     // Ambient temperature (°C)
    EnergyPrice         : REAL;     // Current energy tariff ($/kWh)
    Enable              : BOOL;     // Enable MPC mode
    MaxSpeed            : REAL := 1500.0;  // RPM
    MinSpeed            : REAL := 300.0;   // RPM
END_VAR

VAR_OUTPUT
    SpeedSetpoint       : REAL;     // Optimized speed to VFD (RPM)
    PredictedPower      : REAL;     // Predicted power consumption (kW)
    EnergySaving        : REAL;     // Estimated savings vs. conventional (%)
    EfficiencyIndex     : REAL;     // Current operating efficiency (%)
    Status              : INT;      // 0=Off, 1=Running, 2=Optimizing, 3=Fault
END_VAR

VAR
    // MPC Internal Variables
    PredictionHorizon   : INT := 10;       // Prediction steps
    ControlHorizon      : INT := 3;        // Control moves
    SampleTime          : REAL := 0.1;     // 100ms
    
    // Process Model Parameters (identified online)
    ModelGain           : REAL := 0.85;    // Process gain
    ModelTimeConst      : REAL := 2.5;     // Time constant (s)
    ModelDelay          : REAL := 0.3;     // Dead time (s)
    
    // Optimization Weights
    W_Tracking          : REAL := 1.0;     // Output tracking weight
    W_Energy            : REAL := 0.3;     // Energy minimization weight
    W_DeltaU            : REAL := 0.1;     // Control move smoothness weight
    
    // State Variables
    PrevSpeed           : REAL;
    ErrorIntegral       : REAL;
    ProcessError        : REAL;
    PredictedOutput     : ARRAY[0..19] OF REAL;
    OptimalMoves        : ARRAY[0..4] OF REAL;
    
    // Affinity Law Variables (for pump/fan applications)
    // Power ∝ Speed³, Flow ∝ Speed, Pressure ∝ Speed²
    ReferenceSpeed      : REAL := 1500.0;
    ReferencePower      : REAL;
    ReferenceFlow       : REAL;
    
    // Energy Tracking
    BaselinePower       : REAL;     // Power at full speed
    ActualPower         : REAL;
    CumulativeSavings   : REAL;
    
    // Adaptive Model Parameters
    ModelUpdateCounter  : INT;
    AdaptiveGain        : REAL;
    
    // Internal timers
    OptCycleTimer       : TON;
    i                   : INT;
END_VAR

// ===== MAIN LOGIC =====

IF NOT Enable THEN
    SpeedSetpoint := 0.0;
    Status := 0;
    RETURN;
END_IF;

Status := 2;  // Optimizing

// ---- Step 1: Calculate Process Error ----
ProcessError := ProcessDemand - MeasuredOutput;

// ---- Step 2: Predict Future Outputs (using first-order plus dead time model) ----
FOR i := 0 TO PredictionHorizon - 1 DO
    PredictedOutput[i] := MeasuredOutput + 
        ModelGain * (1.0 - EXP(-1.0 * REAL_TO_LREAL(i) * SampleTime / ModelTimeConst)) 
        * (SpeedSetpoint - PrevSpeed);
END_FOR;

// ---- Step 3: Cost Function Optimization (Simplified MPC) ----
// J = Σ[W_track*(y_pred - y_ref)² + W_energy*(P_pred)² + W_delta*(Δu)²]

// Apply Affinity Laws for power prediction
// P2/P1 = (N2/N1)³ — Cubic relationship
ReferencePower := MotorPower * EXPT(ReferenceSpeed / MAX(SpeedSetpoint, 1.0), 3.0);
BaselinePower := ReferencePower;  // Power at full speed

// Optimal speed calculation using gradient descent approach
SpeedSetpoint := PrevSpeed + 
    W_Tracking * ProcessError * ModelGain -
    W_Energy * 3.0 * MotorPower / MAX(SpeedSetpoint, 1.0) * EnergyPrice -
    W_DeltaU * (PrevSpeed - SpeedSetpoint);

// ---- Step 4: Apply Constraints ----
IF SpeedSetpoint > MaxSpeed THEN
    SpeedSetpoint := MaxSpeed;
ELSIF SpeedSetpoint < MinSpeed THEN
    SpeedSetpoint := MinSpeed;
END_IF;

// Thermal constraint
IF MotorTemp > 130.0 THEN   // Class F insulation limit
    SpeedSetpoint := SpeedSetpoint * 0.9;  // Derate 10%
END_IF;

// Rate of change constraint (max 100 RPM/s for smooth acceleration)
IF ABS(SpeedSetpoint - PrevSpeed) > (100.0 * SampleTime) THEN
    IF SpeedSetpoint > PrevSpeed THEN
        SpeedSetpoint := PrevSpeed + (100.0 * SampleTime);
    ELSE
        SpeedSetpoint := PrevSpeed - (100.0 * SampleTime);
    END_IF;
END_IF;

// ---- Step 5: Calculate Outputs ----
// Predicted power using affinity laws
PredictedPower := BaselinePower * EXPT(SpeedSetpoint / ReferenceSpeed, 3.0);

// Energy savings calculation
IF BaselinePower > 0.0 THEN
    EnergySaving := (1.0 - EXPT(SpeedSetpoint / ReferenceSpeed, 3.0)) * 100.0;
ELSE
    EnergySaving := 0.0;
END_IF;

// Efficiency Index
IF MotorPower > 0.0 AND MeasuredOutput > 0.0 THEN
    EfficiencyIndex := (MeasuredOutput / ProcessDemand) / (MotorPower / BaselinePower) * 100.0;
ELSE
    EfficiencyIndex := 0.0;
END_IF;

// ---- Step 6: Adaptive Model Update ----
ModelUpdateCounter := ModelUpdateCounter + 1;
IF ModelUpdateCounter >= 100 THEN  // Update every 10 seconds
    // Simple recursive least squares for model adaptation
    AdaptiveGain := (MeasuredOutput - PredictedOutput[0]);
    ModelGain := ModelGain + 0.01 * AdaptiveGain;
    ModelGain := LIMIT(0.1, ModelGain, 5.0);
    ModelUpdateCounter := 0;
END_IF;

// ---- Step 7: Update Previous Values ----
PrevSpeed := SpeedSetpoint;
Status := 1;  // Running

            // ADD_M(req:=ModbusRequest, UnitID:=ModbusUnitID,

            Voltage_L1N := WORDS_TO_REAL(RawData[0], RawData[1]);

            Current_L2 := WORDS_TO_REAL(RawData[2], RawData[3]);
            Current_L3 := WORDS_TO_REAL(RawData[4], RawData[5]);

            ApparentPower_Total := WORDS_TO_REAL(RawData[4], RawData[5]);
            PowerFactor := WORDS_TO_REAL(RawData[6], RawData[7]);

            ReadState := 4;
            
        4: // Read Power Quality
            THD_Voltage_L1 := WORDS_TO_REAL(RawData[0], RawData[1]);
            THD_Current_L1 := WORDS_TO_REAL(RawData[2], RawData[3]);

// Quality score (based on data freshness and consistency)
QualityScore := 100.0;
IF NOT CommsOK THEN QualityScore := QualityScore - 50.0; END_IF;
IF NOT DataValid THEN QualityScore := QualityScore - 30.0; END_IF;

BufferIndex := (BufferIndex + 1) MOD 60;

// 1-minute average power

END_IF;

FUNCTION_BLOCK FB_ProcessSequencer
(* Batch process sequence controller *)
(* Controls: Tank filling → Heating → Mixing → Transfer *)

VAR_INPUT
    StartBatch          : BOOL;
    StopBatch           : BOOL;
    EmergencyStop       : BOOL;
    
    // Process measurements
    TankLevel           : REAL;     // 0-100%
    ProcessTemp         : REAL;     // °C
    MixerSpeed          : REAL;     // RPM
    FlowRate            : REAL;     // m³/h
    DischargeConfirm    : BOOL;
    
    // Setpoints
    SP_Level            : REAL := 80.0;    // Fill level target (%)
    SP_Temperature      : REAL := 65.0;    // Process temp target (°C)
    SP_MixerSpeed       : REAL := 500.0;   // Mixing speed (RPM)
    SP_MixTime          : TIME := T#300S;  // Mixing duration
END_VAR

VAR_OUTPUT
    // Actuator commands
    InletValve          : BOOL;
    HeaterEnable        : BOOL;
    HeaterPower         : REAL;    // 0-100%
    MixerRun            : BOOL;
    MixerSpeedCmd       : REAL;    // RPM → sent to VFD
    OutletValve         : BOOL;
    
    // Status
    CurrentStep         : INT;
    StepName            : STRING;
    BatchProgress       : REAL;    // 0-100%
    BatchID             : STRING;
    CycleTime           : TIME;
    EstTimeRemaining    : TIME;
    
    // Alarms
    TempAlarmHigh       : BOOL;
    LevelAlarmHigh      : BOOL;
    MixerFault          : BOOL;
    SequenceFault       : BOOL;
END_VAR

VAR
    State               : INT := 0;
    StepTimer           : TON;
    BatchTimer          : TON;
    HeaterPID           : FB_PID_Controller;
    StepStartTime       : TIME;
    BatchCount          : DINT;
    
    // Step timeout watchdogs
    FillTimeout         : TON;
    HeatTimeout         : TON;
END_VAR

// ===== SAFETY INTERLOCKS (Always Active) =====
IF EmergencyStop THEN
    InletValve := FALSE;
    HeaterEnable := FALSE;
    MixerRun := FALSE;
    OutletValve := FALSE;
    MixerSpeedCmd := 0.0;
    HeaterPower := 0.0;
    State := 99;  // E-Stop state
    StepName := 'EMERGENCY STOP';
    RETURN;
END_IF;

// Over-temperature protection
IF ProcessTemp > 90.0 THEN
    HeaterEnable := FALSE;
    HeaterPower := 0.0;
    TempAlarmHigh := TRUE;
END_IF;

// Over-level protection
IF TankLevel > 95.0 THEN
    InletValve := FALSE;
    LevelAlarmHigh := TRUE;
END_IF;

// ===== SEQUENCE STATE MACHINE =====
BatchTimer(IN := (State > 0 AND State < 90), PT := T#3600S);

CASE State OF

    0: // IDLE
        StepName := 'IDLE - Ready';
        BatchProgress := 0.0;
        IF StartBatch AND NOT StopBatch THEN
            State := 10;
            BatchCount := BatchCount + 1;
            BatchID := CONCAT('BATCH-', DINT_TO_STRING(BatchCount));
        END_IF;
        
    10: // PRE-CHECK
        StepName := 'Pre-Start Checks';
        BatchProgress := 5.0;
        // Verify initial conditions
        IF TankLevel < 5.0 AND ProcessTemp < 40.0 AND NOT MixerRun THEN
            State := 20;
        ELSE
            SequenceFault := TRUE;
            StepName := 'PRE-CHECK FAILED';
        END_IF;
        
    20: // FILLING
        StepName := 'Filling Tank';
        InletValve := TRUE;
        HeaterEnable := FALSE;
        MixerRun := FALSE;
        OutletValve := FALSE;
        BatchProgress := 10.0 + (TankLevel / SP_Level) * 30.0;
        
        FillTimeout(IN := TRUE, PT := T#600S);
        
        IF TankLevel >= SP_Level THEN
            InletValve := FALSE;
            FillTimeout(IN := FALSE);
            State := 30;
        ELSIF FillTimeout.Q THEN
            SequenceFault := TRUE;
            StepName := 'FILL TIMEOUT';
            State := 90;
        END_IF;
        
    30: // HEATING
        StepName := 'Heating';
        InletValve := FALSE;
        HeaterEnable := TRUE;
        MixerRun := TRUE;          // Gentle mixing during heating
        MixerSpeedCmd := SP_MixerSpeed * 0.3;  // 30% speed for circulation
        
        // PID temperature control
        HeaterPID(
            Setpoint := SP_Temperature,
            ProcessVariable := ProcessTemp,
            Kp := 2.5,
            Ki := 0.8,
            Kd := 0.3,
            OutputMin := 0.0,
            OutputMax := 100.0
        );
        HeaterPower := HeaterPID.Output;
        
        BatchProgress := 40.0 + (ProcessTemp / SP_Temperature) * 20.0;
        
        HeatTimeout(IN := TRUE, PT := T#900S);
        
        IF ProcessTemp >= (SP_Temperature - 0.5) THEN
            HeatTimeout(IN := FALSE);
            State := 40;
        ELSIF HeatTimeout.Q THEN
            SequenceFault := TRUE;
            StepName := 'HEAT TIMEOUT';
            State := 90;
        END_IF;
        
    40: // MIXING (at temperature)
        StepName := 'Mixing';
        HeaterEnable := TRUE;       // Maintain temperature
        HeaterPower := HeaterPID.Output;
        MixerRun := TRUE;
        MixerSpeedCmd := SP_MixerSpeed;  // Full mixing speed
        
        StepTimer(IN := TRUE, PT := SP_MixTime);
        BatchProgress := 60.0 + (TIME_TO_REAL(StepTimer.ET) / TIME_TO_REAL(SP_MixTime)) * 20.0;
        
        IF StepTimer.Q THEN
            StepTimer(IN := FALSE);
            State := 50;
        END_IF;
        
    50: // TRANSFER/DISCHARGE
        StepName := 'Discharging';
        HeaterEnable := FALSE;
        HeaterPower := 0.0;
        MixerRun := FALSE;
        MixerSpeedCmd := 0.0;
        OutletValve := TRUE;
        
        BatchProgress := 80.0 + ((SP_Level - TankLevel) / SP_Level) * 18.0;
        
        IF TankLevel < 2.0 THEN
            OutletValve := FALSE;
            State := 60;
        END_IF;
        
    60: // COMPLETE
        StepName := 'Batch Complete';
        BatchProgress := 100.0;
        CycleTime := BatchTimer.ET;
        InletValve := FALSE;
        HeaterEnable := FALSE;
        MixerRun := FALSE;
        OutletValve := FALSE;
        MixerSpeedCmd := 0.0;
        HeaterPower := 0.0;
        
        // Auto-restart or wait
        State := 0;
        
    90: // FAULT STATE
        InletValve := FALSE;
        HeaterEnable := FALSE;
        MixerRun := FALSE;
        OutletValve := FALSE;
        MixerSpeedCmd := 0.0;
        HeaterPower := 0.0;
        
        IF StartBatch THEN  // Acknowledge and restart
            SequenceFault := FALSE;
            State := 0;
        END_IF;
        
    99: // EMERGENCY STOP
        IF NOT EmergencyStop THEN
            State := 0;
        END_IF;
        
END_CASE;

// Stop request handling
IF StopBatch AND State > 0 AND State < 90 THEN
    State := 60;  // Go to orderly shutdown
END_IF;

import numpy as np
import pandas as pd
import tensorflow as tf
from tensorflow.keras.models import Sequential
from tensorflow.keras.layers import LSTM, Dense, Dropout, Bidirectional
from sklearn.preprocessing import MinMaxScaler
from sklearn.metrics import mean_absolute_percentage_error
import paho.mqtt.client as mqtt
import json

class NEXUSEnergyForecaster:
    """LSTM-based energy consumption forecaster for NEXUS-AI system"""
    
    def __init__(self, lookback=96, forecast_horizon=24):
        """
        Args:
            lookback: Number of past timesteps (96 = 24hrs at 15min intervals)
            forecast_horizon: Steps to predict ahead (24 = 6hrs at 15min)
        """
        self.lookback = lookback
        self.forecast_horizon = forecast_horizon
        self.scaler = MinMaxScaler()
        self.model = None
        self.feature_columns = [
            'active_power_kw', 'reactive_power_kvar', 'power_factor',
            'voltage_avg', 'current_avg', 'thd_voltage', 'thd_current',
            'motor_speed_rpm', 'motor_current_a', 'motor_power_kw',
            'motor_temperature_c', 'process_temperature_c',
            'process_pressure_bar', 'process_flow_m3h', 'tank_level_pct',
            'vfd_frequency_hz', 'vfd_efficiency_pct',
            'ambient_temperature_c', 'production_rate',
            'energy_tariff', 'hour_sin', 'hour_cos',
            'day_sin', 'day_cos'
        ]
    
    def build_model(self):
        """Build Bidirectional LSTM model"""
        self.model = Sequential([
            Bidirectional(
                LSTM(128, return_sequences=True, 
                     input_shape=(self.lookback, len(self.feature_columns))),
            ),
            Dropout(0.2),
            
            Bidirectional(LSTM(64, return_sequences=True)),
            Dropout(0.2),
            
            LSTM(32, return_sequences=False),
            Dropout(0.15),
            
            Dense(64, activation='relu'),
            Dense(32, activation='relu'),
            Dense(self.forecast_horizon)  # Predict next 24 steps
        ])
        
        self.model.compile(
            optimizer=tf.keras.optimizers.Adam(learning_rate=0.001),
            loss='huber',  # Robust to outliers
            metrics=['mae', 'mape']
        )
        
        return self.model
    
    def add_time_features(self, df):
        """Add cyclical time features"""
        df['hour_sin'] = np.sin(2 * np.pi * df.index.hour / 24)
        df['hour_cos'] = np.cos(2 * np.pi * df.index.hour / 24)
        df['day_sin'] = np.sin(2 * np.pi * df.index.dayofweek / 7)
        df['day_cos'] = np.cos(2 * np.pi * df.index.dayofweek / 7)
        return df
    
    def prepare_sequences(self, data):
        """Create sliding window sequences for LSTM"""
        X, y = [], []
        for i in range(self.lookback, len(data) - self.forecast_horizon):
            X.append(data[i - self.lookback:i])
            y.append(data[i:i + self.forecast_horizon, 0])  # Predict power
        return np.array(X), np.array(y)
    
    def train(self, df, epochs=100, batch_size=32):
        """Train the forecasting model"""
        df = self.add_time_features(df)
        data = df[self.feature_columns].values
        
        # Scale data
        scaled_data = self.scaler.fit_transform(data)
        
        # Create sequences
        X, y = self.prepare_sequences(scaled_data)
        
        # Split 80/20
        split = int(0.8 * len(X))
        X_train, X_test = X[:split], X[split:]
        y_train, y_test = y[:split], y[split:]
        
        # Train with early stopping
        callbacks = [
            tf.keras.callbacks.EarlyStopping(
                patience=10, restore_best_weights=True
            ),
            tf.keras.callbacks.ReduceLROnPlateau(
                factor=0.5, patience=5
            )
        ]
        
        history = self.model.fit(
            X_train, y_train,
            validation_data=(X_test, y_test),
            epochs=epochs,
            batch_size=batch_size,
            callbacks=callbacks,
            verbose=1
        )
        
        return history
    
    def predict_next_24h(self, recent_data):
        """
        Predict next 24 hours of energy consumption
        Args:
            recent_data: Last 96 timesteps (24hrs) of all features
        Returns:
            Dictionary with predictions and confidence intervals
        """
        scaled = self.scaler.transform(recent_data)
        X = scaled[-self.lookback:].reshape(1, self.lookback, -1)
        
        # Monte Carlo Dropout for uncertainty estimation
        predictions = []
        for _ in range(50):
            pred = self.model(X, training=True)  # Enable dropout
            predictions.append(pred.numpy()[0])
        
        predictions = np.array(predictions)
        
        # Inverse scale the power prediction
        mean_pred = np.mean(predictions, axis=0)
        std_pred = np.std(predictions, axis=0)
        
        return {
            'forecast_kw': mean_pred.tolist(),
            'confidence_lower': (mean_pred - 1.96 * std_pred).tolist(),
            'confidence_upper': (mean_pred + 1.96 * std_pred).tolist(),
            'total_kwh_predicted': float(np.sum(mean_pred) * 0.25),  # 15min intervals
            'peak_predicted_kw': float(np.max(mean_pred)),
            'peak_time_index': int(np.argmax(mean_pred)),
            'uncertainty_pct': float(np.mean(std_pred / mean_pred) * 100)
        }


class NEXUSAnomalyDetector:
    """Autoencoder-based anomaly detection for energy patterns"""
    
    def __init__(self, input_dim=12, encoding_dim=4):
        self.input_dim = input_dim
        self.encoding_dim = encoding_dim
        self.threshold = None
        self.model = self._build_autoencoder()
    
    def _build_autoencoder(self):
        """Build autoencoder for anomaly detection"""
        encoder_input = tf.keras.Input(shape=(self.input_dim,))
        x = Dense(8, activation='relu')(encoder_input)
        x = Dense(self.encoding_dim, activation='relu')(x)
        x = Dense(8, activation='relu')(x)
        decoder_output = Dense(self.input_dim, activation='sigmoid')(x)
        
        model = tf.keras.Model(encoder_input, decoder_output)
        model.compile(optimizer='adam', loss='mse')
        return model
    
    def train(self, normal_data, epochs=50):
        """Train on normal operating data only"""
        self.model.fit(normal_data, normal_data, 
                       epochs=epochs, batch_size=32,
                       validation_split=0.1, verbose=0)
        
        # Set threshold as 95th percentile of training reconstruction error
        reconstructions = self.model.predict(normal_data)
        errors = np.mean(np.square(normal_data - reconstructions), axis=1)
        self.threshold = np.percentile(errors, 95)
    
    def detect(self, data_point):
        """
        Detect anomaly in real-time data
        Returns: (is_anomaly: bool, anomaly_score: float, details: dict)
        """
        data_point = np.array(data_point).reshape(1, -1)
        reconstruction = self.model.predict(data_point, verbose=0)
        error = np.mean(np.square(data_point - reconstruction))
        
        anomaly_score = error / self.threshold  # >1.0 = anomaly
        is_anomaly = anomaly_score > 1.0
        
        # Find which features contribute most to anomaly
        feature_errors = np.square(data_point[0] - reconstruction[0])
        top_contributors = np.argsort(feature_errors)[-3:][::-1]
        
        return {
            'is_anomaly': bool(is_anomaly),
            'anomaly_score': float(anomaly_score),
            'reconstruction_error': float(error),
            'threshold': float(self.threshold),
            'top_contributing_features': top_contributors.tolist(),
            'feature_errors': feature_errors.tolist()
        }


class NEXUSOptimizationEngine:
    """Energy optimization recommendation engine"""
    
    def __init__(self):
        self.recommendations = []
    
    def analyze_and_recommend(self, plant_data):
        """
        Analyze current plant data and generate optimization recommendations
        
        Args:
            plant_data: dict with current plant measurements
        
        Returns:
            List of prioritized recommendations with estimated savings
        """
        self.recommendations = []
        
        # === Rule 1: VFD Speed Optimization (Affinity Laws) ===
        if plant_data.get('motor_load_pct', 100) < 75:
            current_speed_ratio = plant_data['motor_speed'] / plant_data['motor_rated_speed']
            optimal_speed_ratio = (plant_data['process_demand'] / 
                                   plant_data['process_capacity']) ** (1/3)
            
            if current_speed_ratio > optimal_speed_ratio * 1.1:
                current_power = plant_data['motor_power_kw']
                optimal_power = current_power * (optimal_speed_ratio / current_speed_ratio) ** 3
                savings_kw = current_power - optimal_power
                
                self.recommendations.append({
                    'id': 'OPT-001',
                    'category': 'VFD_OPTIMIZATION',
                    'priority': 'HIGH',
                    'title': 'Reduce motor speed to match process demand',
                    'description': f'Motor running at {current_speed_ratio*100:.0f}% speed '
                                   f'but process only needs {optimal_speed_ratio*100:.0f}%. '
                                   f'Reduce speed setpoint to {optimal_speed_ratio * plant_data["motor_rated_speed"]:.0f} RPM.',
                    'savings_kw': round(savings_kw, 1),
                    'savings_annual_usd': round(savings_kw * 8760 * 0.12, 0),
                    'savings_co2_annual_kg': round(savings_kw * 8760 * 0.82, 0),
                    'implementation': 'AUTOMATIC',
                    'confidence': 0.95
                })
        
        # === Rule 2: Power Factor Correction ===
        pf = plant_data.get('power_factor', 1.0)
        if pf < 0.90:
            reactive_power = plant_data['reactive_power_kvar']
            target_pf = 0.95
            # Q_comp = P * (tan(acos(current_pf)) - tan(acos(target_pf)))
            import math
            q_current = math.tan(math.acos(pf))
            q_target = math.tan(math.acos(target_pf))
            q_compensation = plant_data['active_power_kw'] * (q_current - q_target)
            
            # PF penalty savings (typical utility charge)
            pf_penalty = plant_data['active_power_kw'] * (0.90/pf - 1) * 0.05 * 720  # monthly
            
            self.recommendations.append({
                'id': 'OPT-002',
                'category': 'POWER_QUALITY',
                'priority': 'MEDIUM',
                'title': f'Install {q_compensation:.0f} kVAR capacitor bank',
                'description': f'Current PF: {pf:.2f}. Installing {q_compensation:.0f} kVAR '
                               f'capacitor bank will improve PF to {target_pf:.2f}, '
                               f'reducing reactive power charges.',
                'savings_monthly_usd': round(pf_penalty, 0),
                'capex_usd': round(q_compensation * 25, 0),  # ~$25/kVAR
                'payback_months': round(q_compensation * 25 / max(pf_penalty, 1), 1),
                'implementation': 'MANUAL',
                'confidence': 0.90
            })
        
        # === Rule 3: Load Shifting ===
        if plant_data.get('current_tariff') == 'PEAK':
            shiftable_loads = plant_data.get('shiftable_load_kw', 0)
            if shiftable_loads > 0:
                peak_rate = plant_data.get('peak_tariff', 0.18)
                offpeak_rate = plant_data.get('offpeak_tariff', 0.08)
                savings_per_hour = shiftable_loads * (peak_rate - offpeak_rate)
                
                self.recommendations.append({
                    'id': 'OPT-003',
                    'category': 'LOAD_MANAGEMENT',
                    'priority': 'HIGH',
                    'title': 'Shift non-critical loads to off-peak hours',
                    'description': f'{shiftable_loads:.0f} kW of loads can be shifted '
                                   f'to off-peak hours (22:00-06:00). '
                                   f'Save ${savings_per_hour:.2f}/hour during peak.',
                    'savings_daily_usd': round(savings_per_hour * 8, 2),
                    'implementation': 'SEMI-AUTOMATIC',
                    'confidence': 0.85
                })
        
        # === Rule 4: Motor Oversizing Detection ===
        if plant_data.get('motor_load_pct', 100) < 40:
            self.recommendations.append({
                'id': 'OPT-004',
                'category': 'EQUIPMENT_SIZING',
                'priority': 'LOW',
                'title': 'Motor may be oversized - consider right-sizing',
                'description': f'Motor consistently running at '
                               f'{plant_data.get("motor_load_pct", 0):.0f}% load. '
                               f'Motors are most efficient at 75-100% load. '
                               f'Consider replacing with smaller motor during next maintenance.',
                'savings_pct': 5,
                'implementation': 'MANUAL',
                'confidence': 0.70
            })
        
        # === Rule 5: Harmonics Mitigation ===
        thd_i = plant_data.get('thd_current_pct', 0)
        if thd_i > 5.0:
            self.recommendations.append({
                'id': 'OPT-005',
                'category': 'POWER_QUALITY',
                'priority': 'MEDIUM',
                'title': f'Current THD at {thd_i:.1f}% - Install harmonic filter',
                'description': f'THD-I exceeds IEEE 519 limit of 5%. '
                               f'High harmonics cause additional losses in '

                               f'recommended.',
                'additional_losses_pct': round(thd_i * 0.5, 1),
                'implementation': 'MANUAL',
                'confidence': 0.80
            })
        
        # Sort by priority and confidence
        priority_map = {'HIGH': 0, 'MEDIUM': 1, 'LOW': 2}
        self.recommendations.sort(
            key=lambda x: (priority_map.get(x['priority'], 3), -x['confidence'])
        )
        
        return self.recommendations

class NEXUSIoTBridge:
    """Connects edge analytics to cloud via MQTT Sparkplug B"""
    
    def __init__(self, broker_url, port=8883, client_id="NEXUS_Edge_01"):
        self.client = mqtt.Client(client_id)
        self.client.tls_set()  # Enable TLS
        self.client.username_pw_set("nexus_edge", "secure_password")
        self.client.connect(broker_url, port)
        
        self.group_id = "NEXUS_Plant"
        self.node_id = "EdgeGateway_01"
        self.device_id = "PLC_M340"
    
    def publish_telemetry(self, metrics_dict):
        """Publish telemetry data in Sparkplug B format"""
        topic = f"spBv1.0/{self.group_id}/DDATA/{self.node_id}/{self.device_id}"
        
        payload = {
            "timestamp": int(pd.Timestamp.now().timestamp() * 1000),
            "metrics": [],
            "seq": self._get_seq()
        }
        
        for key, value in metrics_dict.items():
            metric = {
                "name": key,
                "value": value,
                "type": "Float" if isinstance(value, float) else "Int32",
                "timestamp": int(pd.Timestamp.now().timestamp() * 1000)
            }
            payload["metrics"].append(metric)
        
        self.client.publish(topic, json.dumps(payload), qos=1)
    
    def publish_alarm(self, alarm_tag, description, priority, value):
        """Publish alarm event"""
        topic = f"spBv1.0/{self.group_id}/ALARM/{self.node_id}"
        payload = {
            "timestamp": int(pd.Timestamp.now().timestamp() * 1000),
            "alarm": {
                "tag": alarm_tag,
                "description": description,
                "priority": priority,
                "value": value,
                "state": "ACTIVE"
            }
        }
        self.client.publish(topic, json.dumps(payload), qos=2)
    
    def publish_recommendation(self, recommendation):
        """Publish optimization recommendation"""
        topic = f"spBv1.0/{self.group_id}/ANALYTICS/{self.node_id}/recommendations"
        self.client.publish(topic, json.dumps(recommendation), qos=1)
    
    def _get_seq(self):
        if not hasattr(self, '_seq_counter'):
            self._seq_counter = 0
        self._seq_counter = (self._seq_counter + 1) % 256
        return self._seq_counter
